# Встраивание Bcf.Core в свой инструмент

`Bcf.Core` — библиотека формата BCF, а не часть плагина Navisworks. Она
собирается под `netstandard2.0`, не имеет внешних зависимостей и ничего
не знает про хост: ни про Navisworks, ни про Revit, ни про окна. Всё, что
привязано к хосту, вынесено в порты — интерфейсы, которые реализует
встраивающий.

Библиотека уже работает в двух ролях: плагин Navisworks выгружает из неё
коллизии Clash Detective, а второй потребитель — агент выгрузки по расписанию —
использует тот же код без единого окна.

## Что берёт на себя библиотека

| | |
|---|---|
| Модель BCF | Замечания, комментарии, точки зрения, камеры — по спецификации buildingSMART, а не по структуре zip |
| Запись | BCF 3.0 и BCF 2.1 — два независимых сериализатора; результат валидируется по официальным XSD в тестах |
| Чтение | Терпимое: чужие статусы и типы сохраняются как есть и попадают в отчёт |
| Обновление | Дописать замечания в существующий архив, не потеряв того, что появилось в нём у приёмника |
| Камера | Перспектива и ортогональ, кватернион → направление и вектор верха, ограничения версий |
| Единицы | Любые единицы хоста → метры BCF |
| Идентификаторы | IFC GUID (сжатие base64 buildingSMART), Revit `UniqueId` → IFC GUID |
| Справочники | Типы, статусы, приоритеты, метки, стадии — из одного файла, с генерацией констант |
| Идемпотентность | Устойчивый ключ замечания: повторная выгрузка не плодит дубли |

Чего библиотека **не** делает: не открывает модели, не рисует снимки, не знает
про лицензии, не показывает окон и не ходит в сеть.

## Порты, которые реализует хост

### `IClashSource` — обязательный

Откуда берутся коллизии.

```csharp
public interface IClashSource
{
    ClashDocumentInfo GetDocument();
    IReadOnlyList<ClashTestInfo> GetTests();
    IEnumerable<ClashItem> EnumerateClashes(ClashTestInfo test, CancellationToken cancellationToken);
    ClashViewpointData CreateViewpoint(ClashItem clash, SnapshotRequest snapshot, CancellationToken cancellationToken);
}
```

`EnumerateClashes` возвращает `IEnumerable`, а не список, намеренно: пять тысяч
коллизий со снимками не должны оказаться в памяти одновременно.

`CreateViewpoint` — единственное место, где хост рисует. Ему передаётся
`SnapshotRequest` с размером кадра, режимом съёмки, способом изоляции и
бюджетом времени; вернуть нужно камеру и, если просили, PNG. Не получилось —
верните `null` или заполните `Warning`: выгрузка не должна падать из-за одного
кадра.

### `ISavedViewpointSource` — необязательный

Замечания, которых нет в проверках на коллизии: прибор повёрнут не той стороной,
труба посреди помещения. Не задан — выгружаются только коллизии.

### `ITopicGuidStore` — необязательный

Карта ранее выданных идентификаторов замечаний. Без неё идентификатор
выводится из устойчивого ключа, и этого достаточно, пока их не начал выдавать
сервер. Готовая файловая реализация — `TopicGuidMap`.

## Минимальный запуск

```csharp
var settings = new BcfExportSettings
{
    Author = "coordinator@example.com",
    ProjectName = "ЖК Северный",
    Version = BcfVersion.Bcf30
};

using (var file = File.Create(@"C:\Выгрузки\коллизии.bcfzip"))
{
    BcfExportResult result = new BcfClashExporter(source, topicGuids, viewpoints)
        .Export(file, settings, progress, cancellationToken);

    if (!result.Succeeded) { /* result.Error, result.Warnings */ }
}
```

Обновление существующего архива — тот же вызов со вторым потоком:

```csharp
using (var existing = File.OpenRead(path))
using (var destination = File.Create(path + ".tmp"))
{
    settings.UpdateMode = BcfUpdateMode.AppendNew;

    var result = exporter.Export(destination, existing, settings);
}
```

Писать поверх исходника нельзя: прерванная запись оставит пользователя без обеих
версий файла. Подменяйте целевой файл после успеха.

## Настройки

Полное описание — [`schemas/api/bcf-export-settings.schema.json`](../schemas/api/bcf-export-settings.schema.json).
Схема сверяется с классом `BcfExportSettings` тестом на каждой сборке: поле,
добавленное в код и забытое в схеме, роняет сборку.

Значения справочников в схеме намеренно не перечислены — их единственный
источник [`bcf-vocabularies/bcf-extensions.json`](../bcf-vocabularies/bcf-extensions.json),
из которого генерируются константы `BcfVocabulary`. Второй список значений
неизбежно разошёлся бы с первым.

## Правила, на которые библиотека опирается

**Строго на запись, терпимо на чтение.** Значение вне справочника при записи —
исключение на этапе сборки замечания. При чтении чужого архива то же значение
сохраняется как есть: стандарт объявляет механизм справочников, но не фиксирует
их содержимое, и файл из BIMcollab или Revizto законно приходит со своими
статусами.

**Инвариантная культура везде.** Числа и даты пишутся через
`CultureInfo.InvariantCulture`. Тесты гоняются на трёх локалях, включая
турецкую.

**Никакого `String.GetHashCode`.** Он рандомизирован по процессам, и выгрузка
перестала бы быть воспроизводимой. Для устойчивых ключей — SHA-256
(`StableTopicKey`), для внутренних — FNV-1a.

**Ничего не пишется в UI и в сеть.** Прогресс идёт через `IProgress<T>`,
отмена — через `CancellationToken`, ошибка возвращается результатом, а
не исключением наружу.

## Сборка и подключение

```
git submodule add https://github.com/kichnap/bimzen-bcf
```

Дальше — ссылкой на проект `Bcf.Core/Bcf.Core.csproj`. Пакета NuGet нет
намеренно: библиотека развивается вместе с потребителями, и сабмодуль даёт
им общую историю.

Тесты `Bcf.Core.Tests` собираются под `net48` и `net8.0` и требуют только
xUnit — Navisworks для них не нужен.

## Запуск готовой выгрузки из Navisworks

Если хост — внешний инструмент, которому нужен не свой экспортёр, а результат
из Navisworks, встраивать `Bcf.Core` не нужно: плагин BIMzen NaVi запускается
файлом задания. Договор — `docs/bcf/job-api.md` в репозитории плагина.
