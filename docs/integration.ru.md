# Встраивание Bcf.Core в свой инструмент

`Bcf.Core` — библиотека формата BCF, а не часть какого-либо приложения. Она
собирается под `netstandard2.0`, не имеет внешних зависимостей и ничего
не знает про хост: ни про приложение моделирования, ни про интерфейс. Всё,
что привязано к хосту, вынесено в порты — интерфейсы, которые реализует
встраивающий.

Библиотека уже работает в двух ролях: внутри настольной надстройки,
выгружающей результаты проверок на коллизии, и внутри агента без интерфейса,
который делает такие же архивы по расписанию.

## Что берёт на себя библиотека

| | |
|---|---|
| Модель BCF | Замечания, комментарии, точки зрения, камеры — по спецификации buildingSMART, а не по структуре zip |
| Запись | BCF 3.0 и BCF 2.1 двумя независимыми сериализаторами; результат проверяется по официальным XSD в тестах |
| Чтение | Терпимое: чужие статусы и типы сохраняются как есть и попадают в отчёт |
| Обновление | Дописать замечания в существующий архив, не потеряв того, что добавил в него приёмник |
| Камера | Перспектива и ортогональ, кватернион в направление и вектор верха, ограничения версий |
| Единицы | Любые единицы хоста в метры, которых требует BCF |
| Идентификаторы | IFC GUID (сжатие base64 buildingSMART), Revit `UniqueId` в IFC GUID |
| Справочники | Типы, статусы, приоритеты, метки, стадии из одного файла, с генерацией констант |
| Идемпотентность | Устойчивый ключ замечания: повторная выгрузка не плодит дубли |

Чего библиотека **не** делает: не открывает модели, не рисует снимки,
не знает про лицензии, не показывает окон и не ходит в сеть.

## Порты, которые реализует хост

### `IClashSource` — обязательный

Откуда берутся коллизии.

```csharp
public interface IClashSource
{
    ClashDocumentInfo GetDocument();
    IReadOnlyList<ClashTestInfo> GetTests();
    IEnumerable<ClashItem> EnumerateClashes(ClashTestInfo test, CancellationToken cancellationToken);
    ClashViewpointData CreateViewpoint(ClashItem clash, SnapshotRequest snapshot, CancellationToken cancellationToken);
}
```

`EnumerateClashes` возвращает `IEnumerable`, а не список, намеренно: пять
тысяч коллизий со снимками не должны оказаться в памяти одновременно.

`CreateViewpoint` — единственное место, где хост рисует. Ему передаётся
`SnapshotRequest` с размером кадра, режимом съёмки, способом изоляции
и бюджетом времени; вернуть нужно камеру и, если просили, PNG. Не получилось —
верните `null` или заполните `Warning`: один кадр не должен ронять всю
выгрузку.

### `ISavedViewpointSource` — необязательный

Замечания, которых логика коллизий не выражает: прибор повёрнут не той
стороной, труба идёт посреди помещения, узел собран не по проекту. Человек
фиксирует такое сохранённым видом, и этот порт превращает их в замечания того
же архива. Не задан — выгружаются только коллизии.

### `ITopicGuidStore` — необязательный

Карта ранее выданных идентификаторов замечаний. Без неё идентификатор
выводится из устойчивого ключа, и этого достаточно, пока их не начал выдавать
сервер. Готовая файловая реализация — `TopicGuidMap`.

## Минимальный запуск

```csharp
var settings = new BcfExportSettings
{
    Author = "coordinator@example.com",
    ProjectName = "Северный квартал",
    Version = BcfVersion.Bcf30
};

using (var file = File.Create(@"C:\exports\clashes.bcfzip"))
{
    BcfExportResult result = new BcfClashExporter(source, topicGuids, viewpoints)
        .Export(file, settings, progress, cancellationToken);

    if (!result.Succeeded) { /* result.Error, result.Warnings */ }
}
```

Обновление существующего архива — тот же вызов со вторым потоком:

```csharp
using (var existing = File.OpenRead(path))
using (var destination = File.Create(path + ".tmp"))
{
    settings.UpdateMode = BcfUpdateMode.AppendNew;

    var result = exporter.Export(destination, existing, settings);
}
```

Писать поверх исходника нельзя: прерванная запись оставит пользователя без
обеих версий. Подменяйте целевой файл только после успеха.

## Настройки

Полное описание —
[`schemas/api/bcf-export-settings.schema.json`](../schemas/api/bcf-export-settings.schema.json).
Схема сверяется с классом `BcfExportSettings` тестом на каждой сборке: поле,
добавленное в код и забытое в схеме, роняет сборку.

Значения справочников в схеме намеренно не перечислены — их единственный
источник
[`bcf-vocabularies/bcf-extensions.json`](../bcf-vocabularies/bcf-extensions.json),
из которого генерируются константы `BcfVocabulary`. Второй список значений
неизбежно разошёлся бы с первым.

## Правила, на которые опирается библиотека

**Строго на запись, терпимо на чтение.** Значение вне справочника при записи —
исключение на этапе сборки замечания. То же значение, прочитанное из чужого
архива, сохраняется как есть: стандарт объявляет механизм справочников,
но не фиксирует их содержимое, и файл из BIMcollab или Revizto законно
приходит со своими статусами.

**Инвариантная культура везде.** Числа и даты пишутся через
`CultureInfo.InvariantCulture`. Тесты гоняются на трёх локалях, включая
турецкую.

**Никакого `String.GetHashCode`.** Он рандомизирован по процессам, и выгрузка
перестала бы быть воспроизводимой. Для идентичности — SHA-256
(`StableTopicKey`), для внутренних хешей — FNV-1a.

**Ничего не уходит в интерфейс и в сеть.** Прогресс идёт через
`IProgress<T>`, отмена — через `CancellationToken`, а ошибка возвращается
результатом, а не летит исключением в вызывающего.

## Сборка и подключение

```
git clone https://github.com/kichnap/bimzen-bcf.git
```

Дальше — ссылкой на проект `Bcf.Core/Bcf.Core.csproj`. Пакет NuGet
(`BimZen.Bcf.Core`) готовится и станет рекомендуемым способом.

Тесты `Bcf.Core.Tests` собираются под `net48` и `net8.0` и требуют только
xUnit — приложение моделирования для их запуска не нужно.
