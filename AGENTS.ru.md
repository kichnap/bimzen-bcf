# Соглашения репозитория

Правила, действующие для любой правки — человеческой или сделанной
ассистентом. Они намеренно короткие: каждое появилось потому, что его
нарушение однажды чего-то стоило.

## Языки

| Где | Язык |
|---|---|
| Код: имена, комментарии `//`, тексты исключений | Английский |
| XML-документация (`/// <summary>`) | Английский **и** русский |
| `README` | Английский, русский, немецкий, нидерландский, финский |
| Остальные документы | Английский и русский |
| Сообщения коммитов | Русский |
| Общение с владельцем репозитория | Только русский |

**Формат двуязычной XML-документации.** Сначала английский абзац, пустая
строка, затем русский. Английская половина излагает контракт, русская чаще
несёт рассуждение — почему решение такое, а не очевидное. Обе половины
правятся вместе: изменить одну и забыть другую хуже, чем иметь одну.

```csharp
/// <summary>
/// Strict on write, lenient on read: a value outside the vocabulary is an
/// error when writing and is preserved as-is when reading someone else's
/// archive.
///
/// Строго на запись, терпимо на чтение: значение вне справочника при записи —
/// ошибка, а при чтении чужого архива оно сохраняется как есть.
/// </summary>
```

Строчные комментарии `//` внутри методов — только английские. Они короткие,
стоят рядом с кодом, который поясняют, и дублирование делает чтение тяжелее,
а не легче.

**Документы идут парами.** `имя.md` на английском и `имя.ru.md` на русском,
с языковой строкой в шапке каждого. У `README` дополнительно есть
`README.de.md`, `README.nl.md` и `README.fi.md`.

## Чего здесь быть не должно

**Названий закрытых проектов.** Репозиторий публичный и самостоятельный.
Не называйте закрытые продукты, которые его встраивают, их репозитории,
структуру их файлов и внутренние пути. Пишите о *хосте*, *потребителе*,
*встраивающем инструменте*.

Названия чужих продуктов — другое дело и остаются: Navisworks, Revit,
Solibri, BIMcollab, IFC, buildingSMART. Без них документация теряет смысл:
«идентификаторы коллизий пересоздаются при сбросе проверки» — это факт
предметной области, а не ссылка на чей-то закрытый код.

**Значений справочника строками.** Каждый тип, статус, приоритет, метка
и стадия приходят из `bcf-vocabularies/bcf-extensions.json` через
сгенерированный `BcfVocabulary`. За этим следит `NoHardcodedVocabularyTests`.

**Зависимостей времени выполнения в `Bcf.Core`.** Библиотека может быть
загружена в процесс, где уже есть её вторая копия. Пакеты только для сборки
с `PrivateAssets="all"` допустимы; всё, что потребителю придётся разрешать
в рантайме, — нет.

**Ссылок на приложение-хост.** Никаких `Autodesk.*` и API надстроек.
Библиотека собирается и тестируется на машине без единого BIM-приложения,
и это проверяет CI, а не добрые намерения.

## Правила, на которые опирается код

- **Инвариантная культура везде.** Числа и даты форматируются через
  `CultureInfo.InvariantCulture`. Тесты гоняются на трёх локалях, включая
  турецкую.
- **Никакого `String.GetHashCode` там, где нужна устойчивость.** Он
  рандомизирован по процессам, и выгрузка перестала бы быть воспроизводимой.
  Для идентичности — SHA-256 (`StableTopicKey`), для внутренних хешей — FNV-1a.
- **Ни интерфейса, ни сети.** Прогресс идёт через `IProgress<T>`, отмена —
  через `CancellationToken`, ошибка возвращается результатом, а не летит
  исключением в вызывающего.
- **Вывод проверяется по официальным XSD в тестах.** Правка, делающая
  валидный архив невалидным, обязана ронять сборку, а не чей-то рабочий день.

## Перед коммитом

```
dotnet test Bcf.Core.Tests/Bcf.Core.Tests.csproj
```

Оба целевых фреймворка должны пройти. Тронули справочник — запустите
генератор; тронули настройки выгрузки — схема в `schemas/api/` сверяется
с классом тестом и сама об этом скажет.
